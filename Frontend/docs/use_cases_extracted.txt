UC-1 Login System
Created By:
SCMS Development Team
Date Created:
09/12/2026
Primary Actor:
Manager, Receptionist, Coach, Member
Secondary Actors:
None
Description:
A registered user accesses the Sports Center Management System (SCMS) and enters his or her account credentials. SCMS verifies the credentials and, if they are valid, grants access to the system according to the user's role.
Trigger:
A user indicates that he or she wants to log into SCMS.
Preconditions:
PRE-1. User has a registered SCMS account.PRE-2. User account is active.PRE-3. User is not currently logged into SCMS.
Postconditions:
POST-1. User is successfully authenticated by SCMS.POST-2. SCMS creates a login session for the user.POST-3. SCMS identifies the user's role and provides access to the functions permitted for that role.POST-4. User is redirected to the appropriate system interface.
Normal Flow:
1.0 Login
User opens the SCMS login page.
SCMS displays the login form.
User enters the account identifier and password.
User submits the login form.
SCMS verifies the account credentials.
SCMS checks that the account is active.
SCMS identifies the user's role.
SCMS creates the user session and displays the appropriate interface.
Alternative Flows:
1.1 User enters invalid credentials
SCMS informs the user that the account identifier or password is incorrect.
User re-enters the login information.
Return to step 3 of the normal flow.
1.2 User forgot password
User selects the password reset option.
SCMS starts UC-04 Reset Password.
After resetting the password, the user returns to the login page.
Exceptions:
1.0.E1 Account is inactive
SCMS informs the user that the account is inactive.
SCMS does not create a user session.
The use case terminates.
Priority:
High
Frequency of Use:
High. The use case is expected to be used by all 4 user roles whenever they access SCMS.
Business Rules:
BR-AUTH-01, BR-AUTH-04
Other Information:
Email is used as the primary username for authentication.
The system should provide access to the password reset function when the user forgets the password.
Authentication must be completed before the user can access protected functions.
Assumptions:
User account information has already been registered in SCMS.
The user's password has been securely hashed before being stored in the database.
Each user has one of the 4 supported primary roles.

Preconditions:
PRE-1. User is logged into SCMS.PRE-2. User has an active account.
Postconditions:
POST-1. The user's profile information is displayed.POST-2. If the password is changed successfully, the new password is securely stored in SCMS.POST-3. The user's account remains associated with the same role.

  The user's email is already registered in SCMS.
  The password reset process can verify ownership of the account.
  Password hashing is performed by SCMS before the new password is stored.

Precondition

Computation
Nếu Học viên gia hạn gói tập khi gói cũ vẫn còn hạn, ngày hết hạn mới = Ngày hết hạn cũ + Thời hạn gói mới. Nếu gói cũ đã hết hạn, ngày hết hạn mới = Ngày gia hạn + Thời hạn gói mới.

Mối quan hệ
Description – Mô tả logic nghiệp vụ
1
ROLE → USER
Mỗi User được gán một Role để xác định vai trò và quyền hạn của User trong hệ thống, ví dụ Manager, Receptionist, Coach hoặc Member.
2
USER → MEMBER_PROFILE
User khi là Member sẽ có thêm Member Profile để lưu các thông tin cá nhân và thông tin liên quan đến việc tập luyện.
3
USER → COACH_PROFILE
User khi là Coach sẽ có thêm Coach Profile để lưu thông tin chuyên môn như chuyên môn, chứng chỉ và kinh nghiệm.
4
USER → STAFF_PROFILE
User khi là Staff sẽ có thêm Staff Profile để lưu thông tin công việc như chức vụ và trạng thái làm việc.
5
MEMBER_PROFILE → MEMBER_SUBSCRIPTION
Một Member có thể đăng ký hoặc mua nhiều Subscription. Mỗi Subscription lưu thông tin về thời gian sử dụng, giá mua và trạng thái của gói.
6
MEMBERSHIP_PACKAGE → MEMBER_SUBSCRIPTION
Membership Package là gói dịch vụ do trung tâm cung cấp, còn Member Subscription là việc một Member thực tế mua hoặc đăng ký gói đó.
7
SPORT → SPORT_CLASS
Một Sport có thể có nhiều Sport Class. Quan hệ này cho biết một lớp học thuộc môn thể thao nào.
8
SPORT_CLASS → CLASS_SCHEDULE
Một Sport Class có thể có một hoặc nhiều Schedule. Schedule xác định lớp học diễn ra vào ngày nào và thời gian nào.
9
ROOM → CLASS_SCHEDULE
Mỗi Schedule được bố trí tại một Room cụ thể, giúp xác định địa điểm diễn ra lớp học.
10
SPORT_CLASS → CLASS_COACH
Class Coach dùng để quản lý việc phân công Coach cho từng Sport Class.
11
COACH_PROFILE → CLASS_COACH
Một Coach có thể được phân công cho nhiều Class. Quan hệ này cho biết Coach nào phụ trách Class nào.
12
MEMBER_PROFILE → CLASS_ENROLLMENT
Khi Member muốn tham gia một lớp học, hệ thống tạo một Class Enrollment để ghi nhận việc đăng ký của Member.
13
SPORT_CLASS → CLASS_ENROLLMENT
Một Sport Class có thể có nhiều Member đăng ký. Class Enrollment kết nối Member với Class mà họ muốn tham gia.
14
MEMBER_SUBSCRIPTION → CLASS_ENROLLMENT
Enrollment có thể sử dụng một Subscription của Member để xác định gói thành viên nào được dùng cho việc tham gia lớp. Quan hệ này có thể để trống khi Member đăng ký theo hình thức drop-in.
15
USER → CLASS_ENROLLMENT
Quan hệ này lưu lại User nào đã thực hiện việc đăng ký lớp. Ví dụ Member tự đăng ký hoặc Receptionist đăng ký thay cho Member.
16
MEMBER_PROFILE → INVOICE
Khi Member phát sinh khoản cần thanh toán, hệ thống tạo Invoice để ghi nhận số tiền mà Member cần trả.
17
INVOICE → INVOICE_ITEM
Một Invoice có thể có nhiều Invoice Item. Mỗi Item đại diện cho một khoản phí cụ thể trong hóa đơn.
18
MEMBERSHIP_PACKAGE → INVOICE_ITEM
Invoice Item có thể tham chiếu đến Membership Package nếu khoản tiền trong Item phát sinh từ việc mua một gói dịch vụ.
19
MEMBER_SUBSCRIPTION → INVOICE_ITEM
Invoice Item có thể liên kết với Subscription cụ thể mà Member đã mua, giúp xác định khoản tiền đó thuộc Subscription nào.
20
CLASS_ENROLLMENT → INVOICE_ITEM
Invoice Item có thể liên kết với Class Enrollment khi việc đăng ký lớp phát sinh chi phí, ví dụ trường hợp Member mua lớp theo hình thức drop-in.
21
INVOICE → PAYMENT
Payment ghi nhận việc thanh toán cho một Invoice, bao gồm số tiền, phương thức thanh toán, trạng thái và thời gian thanh toán.
22
MEMBER_PROFILE → PAYMENT
Quan hệ này xác định Member nào là người thực hiện hoặc liên quan đến khoản thanh toán.
23
USER → PAYMENT
Quan hệ này xác định User nào đã xử lý khoản thanh toán, ví dụ Receptionist thực hiện giao dịch cho Member.
24
USER → NOTIFICATION
User có thể tạo hoặc gửi Notification đến những User khác trong hệ thống.
25
NOTIFICATION → USER_NOTIFICATION
User Notification dùng để xác định một Notification được gửi đến những User nào và quản lý trạng thái nhận thông báo.
26
USER → USER_NOTIFICATION
Quan hệ này xác định User nào nhận Notification và User đó đã đọc thông báo hay chưa.
27
USER → AUDIT_LOG
Audit Log ghi lại các hành động quan trọng do User thực hiện để hệ thống có thể theo dõi lịch sử thay đổi.
28
CORE BUSINESS FLOW
Luồng nghiệp vụ chính của hệ thống là: User → Membership → Class Registration → Invoice → Payment. Notification và Audit Log đóng vai trò hỗ trợ việc thông báo và theo dõi hoạt động.
1. User
User (1) - is a - (1) Member
Nhiệm vụ: Kế thừa / định danh vai trò hội viên.
Mô tả: Một tài khoản người dùng đóng vai trò là khách hàng đăng ký tập luyện tại trung tâm, sở hữu thông tin cá nhân và tài khoản đăng nhập.
User (1) - is a - (1) Coach
Nhiệm vụ: Kế thừa / định danh vai trò huấn luyện viên.
Mô tả: Một tài khoản người dùng được cấp quyền của huấn luyện viên, quản lý giáo án và giảng dạy lớp.
User (1) - is a - (1) Staff
Nhiệm vụ: Kế thừa / định danh vai trò nhân viên vận hành.
Mô tả: Một tài khoản người dùng đóng vai trò lễ tân, kế toán hoặc quản trị viên quản lý trung tâm.
User (1) - registers on behalf - (N) Class Enrollment
Nhiệm vụ: Ghi nhận người trực tiếp thực hiện đăng ký lớp.
Mô tả: Nhân viên lễ tân hoặc chính hội viên (đóng vai trò User) thao tác đăng ký hồ sơ vào lớp học trên hệ thống.
User (1) - marks attendance - (N) Attendance
Nhiệm vụ: Ghi nhận người thực hiện thao tác điểm danh.
Mô tả: Huấn luyện viên hoặc nhân viên phụ trách quét thẻ/chấm công để xác nhận sự có mặt của học viên trong buổi học.
User (1) - assists check-in - (N) Center Check-In
Nhiệm vụ: Ghi nhận nhân sự hỗ trợ ra/vào trung tâm.
Mô tả: Lễ tân hoặc bảo vệ hỗ trợ quét mã/xác thực cho hội viên khi qua cổng check-in.
User (1) - creates - (N) Invoice
Nhiệm vụ: Ghi nhận người lập hóa đơn tài chính.
Mô tả: Nhân viên thu ngân hoặc nhân viên bán hàng tạo lệnh thanh toán gói tập/lớp học cho hội viên.
User (1) - processes - (N) Payment
Nhiệm vụ: Ghi nhận giao dịch viên xử lý tiền.
Mô tả: Nhân viên thu ngân nhận tiền mặt, quẹt thẻ POS hoặc xác nhận giao dịch chuyển khoản từ khách hàng.
User (1) - approves refund - (N) Payment
Nhiệm vụ: Phê duyệt giao dịch hoàn tiền.
Mô tả: Quản lý hoặc nhân viên có thẩm quyền kiểm tra và đồng ý hoàn tiền cho khách hàng khi hủy dịch vụ.
User (1) - sends - (N) Notification
Nhiệm vụ: Gửi thông báo đi.
Mô tả: Một người dùng (thường là nhân viên/HLV) tạo và gửi tin nhắn hoặc thông báo hệ thống đến đối tượng khác.
User (1) - receives - (N) Notification
Nhiệm vụ: Nhận thông báo.
Mô tả: Người dùng nhận các cảnh báo, lịch tập, hóa đơn hoặc nhắc nhở từ hệ thống.
2. Member
Member (1) - purchases - (N) Member Subscription
Nhiệm vụ: Mua gói dịch vụ/hợp đồng hội viên.
Mô tả: Một hội viên có thể sở hữu nhiều gói đăng ký dịch vụ theo thời gian (hết hạn, gia hạn, hoặc mua gói mới).
Member (1) - registers - (N) Class Enrollment
Nhiệm vụ: Ghi danh tham gia lớp học.
Mô tả: Liên kết hội viên với tư cách là học viên chính thức của một lớp học cụ thể.
Member (1) - performs - (N) Center Check-In
Nhiệm vụ: Điểm danh ra/vào trung tâm tập luyện.
Mô tả: Hội viên thực hiện quẹt thẻ hoặc quét mã QR tại cổng kiểm soát để vào trung tâm tập luyện tự do.
Member (1) - for individual - (N) Training Plan
Nhiệm vụ: Gán giáo án tập luyện cá nhân (PT 1:1).
Mô tả: Hội viên được phân bổ các kế hoạch luyện tập riêng biệt theo thể trạng và mục tiêu cá nhân.
Member (1) - achieves - (N) Training Result
Nhiệm vụ: Lưu chỉ số kết quả luyện tập của cá nhân.
Mô tả: Lưu trữ các kết quả đo đạc thể chất (InBody, số đo vòng, mức tạ, nhịp tim) của hội viên sau quá trình tập.
Member (1) - receives - (N) Assignment
Nhiệm vụ: Nhận bài tập về nhà từ huấn luyện viên.
Mô tả: Hội viên được chỉ định bài tập tự luyện ngoài giờ hoặc nhiệm vụ rèn luyện dinh dưỡng.
Member (1) - submits - (N) Assignment Submission
Nhiệm vụ: Nộp kết quả bài tập được giao.
Mô tả: Hội viên tải video thực hiện động tác, hình ảnh hoặc báo cáo bài tập để HLV chấm điểm.
Member (1) - billed on - (N) Invoice
Nhiệm vụ: Quy định người chịu trách nhiệm thanh toán hóa đơn.
Mô tả: Hóa đơn thu tiền được lập đích danh và gửi tới hội viên tương ứng.
Member (1) - makes payment - (N) Payment
Nhiệm vụ: Thực hiện giao dịch trả tiền.
Mô tả: Hội viên thanh toán các khoản phí phát sinh cho trung tâm.
3. Coach
Center (1) - employs coach - (N) Coach
Nhiệm vụ: Quản lý hợp đồng lao động của HLV tại trung tâm.
Mô tả: Một trung tâm (chi nhánh) ký hợp đồng tuyển dụng và quản lý danh sách nhiều HLV làm việc tại đó.
Coach (1) - manages - (N) Class
Nhiệm vụ: Phụ trách quản lý lớp học.
Mô tả: HLV được phân công chịu trách nhiệm chính về mặt chuyên môn và điều phối toàn bộ một lớp học.
Coach (1) - teaches - (N) Class Session
Nhiệm vụ: Đứng lớp giảng dạy buổi cụ thể.
Mô tả: Ghi nhận HLV trực tiếp giảng dạy trong một ca tập nhất định (hỗ trợ trường hợp có HLV dạy thay).
Coach (1) - creates plan - (N) Training Plan
Nhiệm vụ: Thiết kế giáo án tập luyện.
Mô tả: HLV soạn thảo kế hoạch tập luyện, bao gồm các bài tập, cường độ và chu kỳ tập cho học viên hoặc cả lớp.
Coach (1) - records result - (N) Training Result
Nhiệm vụ: Đánh giá và nhập kết quả tập.
Mô tả: HLV kiểm tra, chấm điểm thành tích và ghi chép thông số kỹ thuật tập luyện của học viên.
Coach (1) - assigns - (N) Assignment
Nhiệm vụ: Giao bài tập về nhà.
Mô tả: HLV tạo yêu cầu rèn luyện độc lập cho học viên thực hiện ngoài buổi học chính.
4. Staff
Center (1) - employs staff - (N) Staff
Nhiệm vụ: Quản lý nhân sự vận hành của trung tâm.
Mô tả: Mỗi trung tâm/chi nhánh sở hữu đội ngũ nhân viên riêng (lễ tân, quản lý, tạp vụ).
5. Center
Center (1) - has room - (N) Room
Nhiệm vụ: Quản lý cơ sở vật chất phòng tập.
Mô tả: Một trung tâm được chia thành nhiều không gian/phòng chức năng khác nhau (phòng Yoga, phòng tạ, sàn boxing).
Center (1) - offers package - (N) Membership Package
Nhiệm vụ: Cung cấp danh mục gói dịch vụ.
Mô tả: Trung tâm phát hành và mở bán các gói tập phù hợp với chính sách kinh doanh của cơ sở.
Center (1) - hosts - (N) Class
Nhiệm vụ: Tổ chức các lớp học.
Mô tả: Trung tâm là đơn vị đăng cai tổ chức và cung cấp địa điểm/dịch vụ cho các lớp thể thao.
Center (1) - logs - (N) Center Check-In
Nhiệm vụ: Lưu lịch sử lượt ra/vào cơ sở.
Mô tả: Trung tâm ghi lại toàn bộ nhật ký khách hàng vào tập tự do để kiểm soát lưu lượng và mật độ sử dụng.
Center (1) - issues - (N) Invoice
Nhiệm vụ: Xuất chứng từ tài chính.
Mô tả: Trung tâm (pháp nhân chi nhánh) là bên phát hành hóa đơn thu tiền bán dịch vụ.
6. Room
Room (1) - takes place in - (N) Class
Nhiệm vụ: Xác định phòng học mặc định của lớp.
Mô tả: Một phòng tập được chỉ định làm địa điểm cố định để tổ chức một hoặc nhiều lớp học.
Room (1) - scheduled in - (N) Class Schedule
Nhiệm vụ: Phân bổ phòng vào khung giờ định kỳ.
Mô tả: Gắn phòng chức năng vào thời khóa biểu mẫu của tuần (tránh xung đột trùng lịch phòng).
Room (1) - held in - (N) Class Session
Nhiệm vụ: Xác định phòng thực tế diễn ra ca tập.
Mô tả: Ghi nhận ca tập cụ thể diễn ra tại phòng nào (cho phép đổi phòng linh hoạt nếu có sự cố).
7. Sport
Sport (1) - categorizes - (N) Class
Nhiệm vụ: Phân loại bộ môn cho lớp học.
Mô tả: Xác định lớp học thuộc bộ môn thể thao nào (Kickboxing, Yoga, Pilates, Zumba).
Sport (1) - includes - (N) Exercise
Nhiệm vụ: Phân nhóm thư viện động tác.
Mô tả: Mỗi bộ môn thể thao bao gồm danh sách các động tác/bài tập kỹ thuật đặc thù tương ứng.
8. Exercise
Exercise (1) - is part of - (N) Plan Exercise
Nhiệm vụ: Đưa động tác vào giáo án chi tiết.
Mô tả: Một động tác chuẩn từ thư viện được đưa vào kế hoạch tập kèm theo cấu hình cụ thể (số hiệp, số lần lặp, mức tạ).
9. Membership Package
Membership Package (1) - includes - (N) Member Subscription
Nhiệm vụ: Định nghĩa khuôn mẫu cho thẻ hội viên.
Mô tả: Gói cước (chuẩn hóa giá, quyền lợi, thời hạn) là khuôn mẫu để tạo ra các gói đăng ký thực tế của từng hội viên.
Membership Package (1) - billed for - (N) Invoice
Nhiệm vụ: Ghi nhận khoản thu mua gói tập trên hóa đơn.
Mô tả: Dòng sản phẩm gói cước được liệt kê là lý do thu tiền trên hóa đơn thanh toán.
10. Member Subscription
Member Subscription (1) - covers - (N) Class Enrollment
Nhiệm vụ: Dùng quyền lợi gói thẻ để tham gia lớp.
Mô tả: Thẻ hội viên đang còn hạn hoặc còn lượt tập được dùng để chi trả/cấp quyền cho việc đăng ký lớp học.
Member Subscription (1) - generates invoice - (N) Invoice
Nhiệm vụ: Sinh hóa đơn từ giao dịch mua/gia hạn thẻ.
Mô tả: Việc kích hoạt hoặc gia hạn thẻ hội viên sẽ tạo ra hóa đơn tài chính tương ứng.
11. Class
Class (1) - has schedule - (N) Class Schedule
Nhiệm vụ: Cấu hình lịch định kỳ của lớp.
Mô tả: Lớp học có các khung thời khóa biểu mẫu (ví dụ: Thứ 2-4-6 lúc 18:00 - 19:30).
Class (1) - generates - (N) Class Session
Nhiệm vụ: Phát sinh các ca tập cụ thể.
Mô tả: Dựa trên lịch trình, hệ thống sinh ra từng buổi tập thực tế gắn với ngày tháng năm cụ thể.
Class (1) - has enrollment - (N) Class Enrollment
Nhiệm vụ: Quản lý danh sách học viên của lớp.
Mô tả: Một lớp học duy trì danh sách những học viên đã đăng ký tham gia.
Class (1) - for class - (N) Training Plan
Nhiệm vụ: Áp dụng giáo án chung cho lớp.
Mô tả: Kế hoạch tập luyện được thiết kế dùng chung cho toàn bộ thành viên trong cùng một lớp học.
Class (1) - requires - (N) Assignment
Nhiệm vụ: Giao bài tập chung theo chương trình lớp.
Mô tả: Các bài tập rèn luyện thêm ngoài giờ áp dụng bắt buộc hoặc khuyến khích cho học viên lớp đó.
12. Class Schedule
Class Schedule (1) - instantiates - (N) Class Session
Nhiệm vụ: Khởi tạo buổi tập từ thời khóa biểu mẫu.
Mô tả: Một mẫu thời gian định kỳ (thứ 3 hàng tuần) sẽ tự động sinh ra hàng loạt buổi học thực tế theo từng tuần.
13. Class Session
Class Session (1) - records - (N) Attendance
Nhiệm vụ: Lưu bảng điểm danh của ca học.
Mô tả: Một buổi học cụ thể sẽ lưu lại trạng thái có mặt, vắng mặt hoặc đi muộn của từng học viên.
Class Session (1) - evaluates - (N) Training Result
Nhiệm vụ: Ghi nhận kết quả rèn luyện theo ca.
Mô tả: Ghi lại kết quả, mức tạ hoặc thời gian hoàn thành bài tập của học viên đạt được ngay trong buổi học đó.
14. Class Enrollment
Class Enrollment (1) - tracks - (N) Attendance
Nhiệm vụ: Thống kê lịch sử đi học của một lượt đăng ký.
Mô tả: Ghi nhận toàn bộ quá trình chuyên cần của một học viên xuyên suốt lớp học để tính tỷ lệ tham gia.
Class Enrollment (1) - invoices - (N) Invoice
Nhiệm vụ: Xuất hóa đơn học phí của lớp.
Mô tả: Hồ sơ đăng ký lớp học phát sinh khoản học phí cần thanh toán trên hóa đơn.
15. Training Plan
Training Plan (1) - contains - (N) Plan Exercise
Nhiệm vụ: Cấu trúc các bước tập trong giáo án.
Mô tả: Một giáo án tập luyện hoàn chỉnh bao gồm nhiều mục chi tiết (thứ tự động tác, số set, số rep, thời gian nghỉ).
16. Plan Exercise
Plan Exercise (1) - yields - (N) Training Result
Nhiệm vụ: Đo lường hiệu suất của động tác bài tập.
Mô tả: Bài tập cụ thể trong giáo án mang lại kết quả thực tế (ví dụ: kế hoạch yêu cầu Squat 60kg, kết quả đạt 65kg).
17. Assignment
Assignment (1) - has submission - (N) Assignment Submission
Nhiệm vụ: Tiếp nhận bài nộp của học viên.
Mô tả: Một đề bài tập về nhà có thể nhận về nhiều lượt nộp bài từ các học viên khác nhau hoặc các lần nộp lại.
18. Invoice
Invoice (1) - paid via - (N) Payment
Nhiệm vụ: Ghi nhận thanh toán cho hóa đơn.
Mô tả: Một hóa đơn có thể được thanh toán qua nhiều lần trả tiền hoặc kết hợp nhiều hình thức (ví dụ: trả trước 50% tiền mặt, 50% quẹt thẻ).
